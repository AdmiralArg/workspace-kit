# Self-improving rule and memory loops for coding agents (2025-2026)

Scope: how practitioners make a coding-agent setup improve over time (capture, storage, promotion, pruning), what Anthropic officially says, and what evidence exists for and against. Research date: 10 November 2026. Star counts and push dates are from the GitHub API on that date. Items marked (older) predate 2026 or could not be dated.

## 1. What is compound engineering (Every, Klaassen, Shipper) and what exactly does the compound step write?

### Takeaway
Compound engineering is Every's agent workflow: plan, work, review, compound, with roughly 80 percent of effort in plan and review and 20 percent in work and compound. The "compound" step writes lessons into the repo (a `docs/solutions/` learning doc, and sometimes a rule or CLAUDE.md/AGENTS.md edit), and the 2026 plugin has since matured the step into a "cheapest durable form" ladder (test or lint rule, then coding standard, then learning doc) with a refresh/worth-audit pass to delete stale learnings.

### Cited Findings
- Every's article "Compound Engineering: How Every Codes With Agents" (Dan Shipper with Kieran Klaassen) defines the loop as Plan, Work, Review, Compound. Plan: agents research the codebase and commit history and write a plan file or GitHub issue. Work: agent builds from a to-do list, using Playwright or XcodeBuildMCP to check its own result. Review: self-review plus human review, with 12 parallel review subagents in Every's plugin. Compound: bugs, performance problems and new solutions are written down for future agents. Publication date not shown on the fetched page. — [Every, Chain of Thought](https://every.to/chain-of-thought/compound-engineering-how-every-codes-with-agents)
- The article calls compound "the money step", states the 80/20 split ("Roughly 80 percent ... is in the plan and review parts, while 20 percent is in the work and compound"), and says learnings live "inside of your codebase or in plugins" as prompts or rules so "every developer on your team gets them for free." It names no specific files. Examples: rules on where new code belongs (with concrete examples from past mistakes in the Cora codebase) and condensed summaries of code review comments. — [Every, Chain of Thought](https://every.to/chain-of-thought/compound-engineering-how-every-codes-with-agents)
- Kieran Klaassen's Every guide lists what compound writes: categorized solution docs in `docs/solutions/` with YAML frontmatter (tags, metadata, categories), additions to CLAUDE.md, new agents when warranted, and a self-check "would the system catch this automatically next time". It also states a "50/50 rule" (half of engineering time on features, half on system improvements). The guide does not discuss pruning or expiry of old learnings. — [Every guide, Klaassen](https://every.to/guides/compound-engineering)
- The plugin repo (EveryInc/compound-engineering-plugin): about 26,005 stars, last push 2026-11-09, latest release 3.37.1 on 2026-11-09, MIT, 37 skills, runs on 14 agent hosts (Claude Code, Cursor, Codex, OpenCode and others). Maintained by Kieran Klaassen and Trevin Chow. — [GitHub repo](https://github.com/EveryInc/compound-engineering-plugin), [README](https://github.com/EveryInc/compound-engineering-plugin/blob/main/README.md), [releases](https://github.com/EveryInc/compound-engineering-plugin/releases)
- 2026 plugin loop is now six steps: `/ce-brainstorm`, `/ce-plan`, `/ce-work`, `/ce-simplify-code`, `/ce-code-review`, `/ce-compound`, plus `/lfg` for the full pipeline autonomously. `/ce-compound` writes to `docs/solutions/` and plans go to `docs/plans/`; `docs_root` in `.compound-engineering/config.yaml` can move both. — [README](https://github.com/EveryInc/compound-engineering-plugin/blob/main/README.md)
- `ce-compound` has a strict "worth compounding" gate: a learning must be non-obvious (not recoverable from final code, tests, types, comments or docs), durable, and material. Counterfactual test: "if the learning document disappeared, would a future engineer reading the final implementation still be likely to repeat the mistake or redo substantial investigation? If not, do not compound." Completion, effort and diff size do not establish eligibility. — [ce-compound guide](https://github.com/EveryInc/compound-engineering-plugin/blob/main/docs/guides/ce-compound.md), [SKILL.md](https://github.com/EveryInc/compound-engineering-plugin/blob/main/skills/ce-compound/SKILL.md)
- It picks the cheapest form that stops the repeat, in order: (1) one owner and one way (change product code, reported for the owner), (2) a test or lint rule, kept only after seeing it pass on the current tree and fail on the defect in a throwaway copy, (3) a rule in `CODING_STANDARDS.md` (never creates the file), (4) a learning doc, only for reasoning other forms cannot carry (measured facts, rejected alternatives). At most one test/rule and one doc per run; "one learning per run"; it never changes product code. — [ce-compound guide](https://github.com/EveryInc/compound-engineering-plugin/blob/main/docs/guides/ce-compound.md)
- Learning doc structure: symptoms, root cause, what did not work, working solution, prevention (bug track); context, guidance, why it matters, when to apply, examples (knowledge track). Closed enums for `problem_type`, `severity`, `resolution_type`; optional `retire_when` field names the external change that would retire the learning. Overlap check scores five dimensions (problem, root cause, solution approach, files, prevention rules): 4-5 matching updates the existing doc, 2-3 creates a new doc and flags for consolidation. — [ce-compound guide](https://github.com/EveryInc/compound-engineering-plugin/blob/main/docs/guides/ce-compound.md)
- Grounding validation: a script checks cited repo paths, commit SHAs and links; a read-only validator subagent verifies code-behavior claims by quoting the defining source line. Full mode also probes session history across Claude Code, Codex, Cursor, Pi from `~/.claude/projects/` etc. — [ce-compound guide](https://github.com/EveryInc/compound-engineering-plugin/blob/main/docs/guides/ce-compound.md)
- Discoverability check: each run checks that AGENTS.md or CLAUDE.md would lead a future agent to `docs/solutions/`; interactive runs propose the smallest addition and ask consent; non-interactive reports the gap without editing. — [ce-compound guide](https://github.com/EveryInc/compound-engineering-plugin/blob/main/docs/guides/ce-compound.md)
- Refresh with a "worth audit": audits existing learnings against the codebase, deleting those whose every claim is recoverable from a named in-repo artifact, shortening those partly recoverable, keeping the rest; also removes or narrows `CODING_STANDARDS.md` rules a check now covers. Entry bar for standards: the defect class must have appeared in a fixed review finding, a fix commit, a codebase-wide cleanup, or a solution record, and no check covers it. — [worth-audit.md](https://github.com/EveryInc/compound-engineering-plugin/blob/main/skills/ce-compound/references/refresh/worth-audit.md)
- Boris Cherny (Claude Code creator) says he borrowed the term "compounding engineering" from Dan Shipper, per secondary reporting; originals (X thread, podcast) were not reached. — [Implicator summary of search results via WebSearch](https://www.implicator.ai/the-accidental-architect-how-boris-cherny-built-silicon-valleys-most-talked-about-coding-tool/)

### Inferences
- The 2025 version of compound ("write it down in docs/solutions and CLAUDE.md") had no removal process; the 2026 plugin added the durable-bar, cheapest-form ladder and refresh/worth-audit precisely because capture-only loops accrete. A kit's /retro should copy the gate and the ladder, not the original "capture everything" framing.
- The "cheapest form" ladder (check > standard > learning) maps directly onto Anthropic's guidance that hooks and checks beat prose for must-hold rules (see section 4), so the two sources agree.
- For a non-code workspace (docs, glossary, decisions), "test or lint rule" translates to the docs lint the kit already has: a correction that can be a lint check should become one before it becomes a prose rule.
- The `retire_when` field and the refresh counterfactual ("is it recoverable from a named artifact") are cheap, adoptable devices for expiry.

### Gaps
- Exact publication date of Every's original compound-engineering article not found.
- Whether the compound step measurably improves outcomes at Every: no measurements found, only Every's own claims.
- Cherny's original statement about borrowing the term was not verified against a primary source.

## 2. How do people capture learnings automatically, and how do they decide what is worth keeping?

### Takeaway
Three capture patterns dominate: (a) correction-detection hooks that queue learnings for human-reviewed promotion (claude-reflect), (b) end-of-session or end-of-task retro/knowledge-update skills (Every's /ce-compound, "update-knowledge" style skills, reflect skills writing AGENTS.md), and (c) fully automatic observation and memory stores (claude-mem, ECC instincts, Claude Code auto memory, Codex memories, Hermes, SkillOpt-Sleep). The more careful systems gate on durability and human approval; the automatic ones lean on confidence scores, scoping and consolidation.

### Cited Findings
**Claude-reflect (closest to the planned /retro)**
- BayramAnnakov/claude-reflect: 1,931 stars, last push 2026-10-03, v3.3.1, 332 tests, MIT. Flow: hook captures corrections into a queue, `/reflect` shows a review table (Apply / Edit / Skip), approved items are written to `~/.claude/CLAUDE.md`, `./CLAUDE.md`, subdirectory CLAUDE.md files, `.claude/commands/*.md` skill files, AGENTS.md, and docs reachable by `@` includes. — [README](https://github.com/BayramAnnakov/claude-reflect)
- Capture hooks: `session_start_reminder.py` (SessionStart), `capture_learning.py` (every prompt, regex for "no, use X", "don't use Y", "actually...", positive feedback, and explicit `remember:` markers), `check_learnings.py` (before compaction), `post_commit_reminder.py` (after git commit). Each learning has a confidence score 0.60-0.95; regex is then validated semantically during `/reflect` to filter false positives. Filters out questions, one-time task instructions, context-specific requests and vague feedback. — [README](https://github.com/BayramAnnakov/claude-reflect)
- Extra commands: `/reflect --scan-history` (past sessions), `--dedupe` (consolidate similar entries), `--review` (confidence and decay status), `/reflect-skills` (mines repeating requests across sessions and generates skill drafts, e.g. 15 similar requests becomes `/daily-review`). Skill-routing: a correction made during `/deploy` can be routed back into the deploy skill file. — [README](https://github.com/BayramAnnakov/claude-reflect)
- v3.3 adds a "reflect-mod" (Claude Code mods, 2.1.286+): every short prompt goes to a one-shot Haiku check that decides whether it holds a reusable rule, shows a band above the prompt with Save / Global-or-repo / Edit / Skip, saves a bullet inside a marked section of CLAUDE.md, repeats merge with a count. Nothing is written without a press. — [README](https://github.com/BayramAnnakov/claude-reflect)
- Open issues show real failure modes: closures and questions queued as 0.85-confidence learnings (#43), proposing rules the user's instructions already cover (#53), Windows path bugs (#48, #49). — [issues](https://github.com/BayramAnnakov/claude-reflect/issues)

**Retro/knowledge-update skills and practitioner patterns**
- Wisetax team outgrew CLAUDE.md (700+ lines) and moved to `.claude/knowledge/` (one markdown file per topic, versioned, PR-reviewed) with a routing table in CLAUDE.md. A custom end-of-session `/update-knowledge` skill reviews conversation plus git diff, edits or creates knowledge files and trims stale content. Keep-test: "would it help Claude three months later"; excluded: changed-file lists, config values, signatures, session logs, deprecated features. CLAUDE.md changes only every few weeks. — [DEV Community, szkjn](https://dev.to/szkjn/we-outgrew-claudemd-building-a-knowledge-layer-that-compounds-33f)
- Eric J Ma's self-improving loop: watch agent traces for an overcomplicated path, a missed file or a global refactor where a surgical fix was needed; classify the fix (repo-specific rule goes to AGENTS.md, repeatable output-bound procedure goes to a skill); "start repo-local, promote to global only after feeling the same pain twice". Anecdotal; no measurements; no pruning discussed. — [Eric J Ma, Jan 2026](https://ericmjl.github.io/blog/2026/1/19/how-to-build-self-improving-coding-agents-part-3)
- Geoffrey Huntley's "signs" idea (secondary write-ups only): when the agent errs, adjust the prompt, adding a sign for each failure; the Ralph Playbook keeps AGENTS.md to about 60 lines of build/test commands and treats the implementation plan file as disposable and regenerable. Details differ between write-ups. — [Ralph Playbook](https://claytonfarr.github.io/ralph-playbook)
- Boris Cherny's team: one shared CLAUDE.md in git, the whole team adds a note whenever Claude does something wrong; he tags `@.claude` on coworkers' PRs to add learnings; file was about 2.5k tokens in early 2026. Also: slash commands in `.claude/commands/` for repeated tasks (`/commit-push-pr` runs dozens of times a day), a PostToolUse formatting hook, and verification (tests, browser) described as the most important tip, "2-3x" improvement. — [InfoQ, Jan 2026](https://infoq.com/news/2026/01/claude-code-creator-workflow/)
- Claude Code docs say when to add to CLAUDE.md: "Claude makes the same mistake a second time", a code review catches something Claude should have known, you type the same correction as last session, or a new teammate would need the same context. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Anthropic's "build your setup over time" table gives the same trigger-to-artifact mapping: wrong twice goes to CLAUDE.md; same starting prompt goes to a user-invocable skill; same playbook pasted for the third time goes to a skill; "something to happen every time" goes to a hook; second repo needs it goes to a plugin. "A repeated mistake or a recurring review comment is a CLAUDE.md edit, not a one-off correction in chat. A workflow you keep tweaking by hand is a skill that needs another revision." — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)

**Automatic or background systems**
- Claude Code auto memory: Claude writes four note types (`user`, `feedback`, `project`, `reference`) as files with YAML frontmatter under `~/.claude/projects/<project>/memory/`, plus a `MEMORY.md` index. It skips anything derivable from the codebase or already in CLAUDE.md, and "doesn't save something every session"; it decides by whether it would be useful in a future conversation. Memory writes record a `modified` timestamp. Machine-local, shared across worktrees of one repo, not across machines. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Anthropic's Dreams (Managed Agents API, research preview, beta header `dreaming-2026-04-21`): an async job that takes a memory store plus 1-100 past sessions and outputs a new reorganized store with duplicates merged, stale or contradicted entries replaced and new insights surfaced. Input store is never modified, so output can be reviewed and discarded. Docs say the pipeline is a synthesis pass, not a line editor. Bill is at standard token rates; start with a small batch. — [Dreams docs](https://platform.claude.com/docs/en/managed-agents/dreams)
- "Auto dream" inside Claude Code was reported in March 2026 from the binary and a `/memory` toggle (v2.1.83), not an official feature at the time; reported behavior is periodic background pruning, merging and date-normalizing of memory files. Details (24h and five-exchange trigger, lock file) come from blogs and are unverified. — [Tessl, 26 Mar 2026](https://tessl.io/blog/anthropic-tests-auto-dream-to-clean-up-claudes-memory/), [Implicator](https://www.implicator.ai/anthropic-adds-auto-dream-to-claude-code-fixing-memory-decay-between-sessions)
- Codex memories (OpenAI): opt-in; turns eligible idle chats into local memory files under `~/.codex/memories_v2/`, redacts secrets, skips active or short sessions, has a consolidation model setting; files are generated state, not to be hand-edited; docs say required team guidance belongs in AGENTS.md or checked-in docs since memories are "a helpful recall layer". — [Codex memories docs](https://learn.chatgpt.com/docs/customization/memories?surface=app)
- Cursor: Memories UI was removed around Cursor 2.1 (about Nov 2025) with staff suggesting moving memories into Rules; "Generate Cursor Rules" command also removed. Sources disagree whether the underlying memory still works. — [Cursor forum](https://forum.cursor.com/t/memories-not-showing/143820), [Cursor forum](https://forum.cursor.com/t/are-my-memories-gone/144057), [Cursor forum](https://forum.cursor.com/t/why-were-generate-cursor-rules-removed/140847)
- ECC "continuous-learning-v2" (affaan-m/ECC, 300,213 stars, last push 2026-11-09): PreToolUse/PostToolUse hooks write observations; a background Haiku observer detects corrections, error resolutions and repeated workflows and writes "instincts" (atomic YAML, one trigger and one action, confidence 0.3-0.9, evidence list, scope project or global). v2.1 isolates instincts per project (hash of git remote) and promotes to global when seen in 2+ projects; `/evolve` clusters instincts into skills, commands or agents. — [SKILL.md](https://github.com/affaan-m/ECC/blob/main/skills/continuous-learning-v2/SKILL.md)
- claude-mem (thedotmack, 115,384 stars, last push 2026-11-09, v15.14.0): captures everything the agent does, compresses it with AI, injects a compact layered index at session start, progressive-disclosure search (index, timeline, details), `<private>` tags. Heavy automatic recall rather than curated rules. Star count is very high; no outcome evidence found. — [README](https://github.com/thedotmack/claude-mem)
- obra/episodic-memory (Jesse Vincent, 499 stars, last push 2026-09-10): indexes conversations at session end, semantic search over past sessions via MCP, for Claude Code, Codex, Cursor, OpenCode. README's evidence is an AI testimonial, not measurements. — [README](https://github.com/obra/episodic-memory)
- obra/superpowers (315,123 stars, last push 2026-11-03): no automatic learning loop. Its `writing-skills` skill treats skill creation as TDD: run a pressure scenario with a subagent without the skill (watch it fail, record exact rationalizations), write a minimal skill, re-verify, close loopholes. "If you didn't watch an agent fail without the skill, you don't know if the skill teaches the right thing." Don't create skills for one-off solutions, project-specific conventions (those go in the instruction file) or mechanical constraints enforceable by validation. A `diagnosing-superpowers` skill reads session transcripts to explain misbehavior. — [writing-skills SKILL.md](https://github.com/obra/superpowers/blob/main/skills/writing-skills/SKILL.md), [README](https://github.com/obra/superpowers)
- Microsoft SkillOpt (18,961 stars, last push 2026-11-07, NeurIPS 2026 spotlight per README): treats a skill document as the trainable state; an optimizer proposes bounded add/delete/replace edits and accepts an edit only if it strictly improves a held-out validation score. Reports gains of +19.1 points inside Claude Code (GPT-5.5 target) on its benchmarks, with deployed skills typically 300-2,000 tokens. Authors' own numbers. — [README](https://github.com/microsoft/SkillOpt)
- SkillOpt-Sleep (preview, v0.2.0, July 2026): nightly cycle that harvests Claude Code/Codex/Copilot/Cursor/Pi/OpenCode transcripts, mines recurring tasks, replays them, consolidates behind a held-out gate, and stages a proposal for human adoption. Warns that real backends send transcript excerpts to the provider. — [SkillOpt-Sleep docs](https://github.com/microsoft/SkillOpt/blob/main/docs/sleep/README.md)
- Hermes Agent (Nous Research): built-in loop of memory nudges, autonomous skill creation, skill refinement during use, cross-session recall; skills stored as markdown in `~/.hermes/skills/`. The "rewrites skills every 15 tasks" and "40% faster" claims are unverified. Docs and third-party overviews disagree on the loop structure. — [Hermes docs](https://hermes-agent.nousresearch.com/docs), [AI Nauten](https://news.ainauten.com/en/story/how-hermes-ai-agent-learns-from-its-own-mistakes-rewrites-its-own-skills-after-every-15-tasks)

**Hooks available for capture**
- Claude Code hook events relevant to a retro loop: `SessionStart` (can inject context), `UserPromptSubmit` (can add context), `PreCompact` (can block; stdout becomes compaction instructions), `PostCompact`, `Stop` (exit 2 keeps Claude working; can add context), `SessionEnd` (side effects only, 1.5-second default budget, so heavy work must be detached), `InstructionsLoaded` (logs which CLAUDE.md and rules loaded). — [Hooks reference](https://code.claude.com/docs/en/hooks)

### Inferences
- Systems that write directly to instruction files without a human step (instincts, auto-promotion) are the ones with false-positive issues in the tracker; the successful widely-used pattern is queue, then human-reviewed promotion, matching the planned /retro.
- Decision criteria converge: durable (not one-off), non-derivable from code/git, repeated (second or third occurrence), scoped (project vs global), and reviewed. Confidence scores (reflect 0.60-0.95, ECC 0.3-0.9) are heuristics with no published calibration.
- The planned /retro can be a command that (1) reads the work log and recent corrections, (2) classifies each candidate into: lint check, rule, skill, glossary term, decision, or discard, (3) shows a table for approval. That mirrors claude-reflect's table, Every's ladder and Anthropic's trigger table.
- SessionEnd's 1.5-second budget makes it unsuitable for model-based reflection; a Stop-hook nudge, SessionStart reminder of queued items, or an explicit /retro is the viable path.
- Auto memory already covers "feedback" and "user" notes; the kit should not duplicate that, and should reserve its own files for shared, versioned, reviewed knowledge (auto memory is machine-local and unversioned).

### Gaps
- No controlled evidence that any capture system (claude-reflect, ECC instincts, claude-mem) improves task outcomes; stars and testimonials only.
- "Auto dream" mechanics in Claude Code remain unofficial.
- Steve Yegge and Harper Reed practices were not researched (time limit); no primary sources fetched for them.
- Simon Willison: only found his 18 September 2026 note that from Claude Code 2.1.277 a folder with no CLAUDE.md falls back to AGENTS.md; no post of his on self-improvement loops was found.

## 3. How do people prevent rule bloat (pruning, consolidation, size limits, moving rules into skills/hooks, progressive disclosure)?

### Takeaway
Consistent advice: keep always-loaded files tiny and specific, move procedures to skills and path-scoped rules, convert must-hold rules into hooks or lint checks, and run periodic consolidation with an audit tool. Tools now exist for each step (`/doctor prompt-audit`, `/reflect --dedupe`, `ce-compound refresh`, auto-memory size reminders, Dreams), but none is automatic for CLAUDE.md itself.

### Cited Findings
- Official size limit: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Imports do not reduce context cost. Contradicting instructions: "Claude may pick one arbitrarily"; review CLAUDE.md, nested files and `.claude/rules/` periodically. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Auto memory index: only the first 200 lines or 25KB of `MEMORY.md` load at session start; after a write near the limit Claude Code reminds Claude to "keep one line per entry, move detail into topic files, and merge or drop stale entries", and over the limit it returns an error telling Claude to rewrite the index because everything past the limit is dropped. Topic files load on demand. CLAUDE.md files themselves have no 200-line cut (whole file loads up to 4 MiB). — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- `/doctor prompt-audit` (v2.1.283+): scans CLAUDE.md, CLAUDE.local.md, AGENTS.md, rules, skills, commands, subagents and output styles for instructions written for older models, references to missing files or commands, and contradictions; reports proposed edits and changes nothing until asked. `/doctor` also proposes trims for things Claude can work out from code. — [Claude Code memory docs](https://code.claude.com/docs/en/memory), [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Anthropic best practices: a CLAUDE.md line costs attention "on every task, whether it's relevant or not", so include only what Claude "couldn't work out from the code itself". "If Claude keeps ignoring a line that is in CLAUDE.md, adding IMPORTANT probably won't fix it. Either the file has grown long enough that the line gets lost, or the line is a rule that can't have exceptions, in which case it belongs in a hook." The emphasis anti-pattern: current models follow plain wording and "piling on emphasis mostly makes Claude over-apply the rule." Don't describe architecture and file layout in CLAUDE.md. — [Best practices](https://code.claude.com/docs/en/best-practices)
- Anthropic also warns against too many hooks: "If you ever find yourself at forty of them, most are probably preferences that Claude could have weighed on its own." A hook is for a rule with zero exceptions. — [Best practices](https://code.claude.com/docs/en/best-practices)
- Anthropic's steering post: own and review CLAUDE.md like code (assign an owner); move team conventions into path-scoped rules and procedures into skills as the file grows; root CLAUDE.md should be treated as an overview or index; keep under 200 lines. — [Claude blog, Steering Claude Code](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)
- Path-scoped rules: `.claude/rules/*.md` with `paths:` frontmatter load only when matching files are opened; unscoped rules load at launch like CLAUDE.md; `paths` is the only frontmatter field read. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Skills as progressive disclosure: only name and description load every session; full body loads on use; skill body under 500 lines; references one level deep; descriptions max 1,024 characters, third person, with what and when; `disable-model-invocation: true` removes the description from context. "The context window is a public good." "Does this paragraph justify its token cost?" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Skill best practice also says avoid time-sensitive info (use an "old patterns" section), use consistent terminology, and build evaluations before writing extensive documentation (identify gaps without the skill, three scenarios, baseline, minimal instructions). — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Anthropic engineering on context: "Context, therefore, must be treated as a finite resource with diminishing marginal returns"; prefer the "right altitude" system prompt and start minimal, adding detail "based on observed failures"; hybrid retrieval where CLAUDE.md is loaded up front and the rest just in time. — [Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Consolidation tooling: `/reflect --dedupe` (claude-reflect), `ce-compound refresh` with overlap scoring and worth-audit deletion (Every), `/update-knowledge` trimming stale content (Wisetax), Dreams and reported auto-dream (Anthropic, memory stores only). Sources cited in sections 1 and 2.
- Reported counterpoint on Cherny: a secondhand article (Geeky Gadgets via AI Nauten, 1 Aug 2026) says he advised deleting a bloated CLAUDE.md for precision; no verbatim quote or primary post was found, so treat as unconfirmed. Nauti's own take: trimming helps solo developers, teams risk losing undocumented shared context. — [AI Nauten](https://news.ainauten.com/en/story/claude-code-erfinder-boris-cherny-raet-loesch-deine-claudemd)
- Instruction-density research (older, July 2025): IFScale tested 20 models with up to 500 simultaneous instructions; best frontier models reached only 68 percent at 500, errors are mostly omissions, with a bias toward earlier instructions. This is a synthetic keyword-inclusion task, not a coding-agent test. — [arXiv 2507.11538](https://arxiv.org/html/2507.11538v1)
- Context rot (older, July 2025): Chroma's report of 18 LLMs found performance degrades non-uniformly as input length grows, with distractors compounding it. Details are from secondary summaries. — [Chroma research](https://trychroma.com/research/context-rot)

### Inferences
- A kit that ships a lint for the instruction files (line count, duplicate lines, dead path references, contradiction candidates) automates what Anthropic recommends doing manually and what `/doctor prompt-audit` does generically; the kit's docs lint should add a check that every rule has a date or source and a "retire when" or review-by field.
- Practical layering for the kit: CLAUDE.md as short index and always-on rules (well under 200 lines), `.claude/rules/` with `paths` for area rules, skills for procedures, hooks or lint for zero-exception rules, a versioned `knowledge/` or `design/` folder routed to by table for depth. This matches Anthropic's own layering, Wisetax's knowledge layer and CE's `docs/solutions/` discoverability line.
- Every promoted rule should record why it exists and what would retire it (CE `retire_when`; Anthropic's "instructions written for older models" audit category shows model upgrades make rules obsolete).

### Gaps
- No primary source for the claim that Claude Code's system prompt consumes about 50 instruction "slots"; appears only in secondary blogs.
- No published threshold for how many rules or tokens of CLAUDE.md degrade adherence beyond the official 200-line rule of thumb.

## 4. What does Anthropic officially recommend for CLAUDE.md, memory, skills and hooks?

### Takeaway
Anthropic's position: CLAUDE.md is for short, specific, always-on facts (under 200 lines); auto memory holds Claude's own notes (200-line/25KB index limit); skills hold on-demand procedures and reference; path-scoped rules hold area conventions; hooks, deny rules and managed settings hold anything that must happen every time. Instruction files are context, not enforcement.

### Cited Findings
- Two memory systems, both loaded each conversation: CLAUDE.md (you write; instructions and rules) and auto memory (Claude writes; learnings and patterns). "Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead. The more specific and concise your instructions, the more consistently Claude follows them." — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Concrete specificity examples: "Use 2-space indentation" instead of "Format code properly"; "Run `npm test` before committing" instead of "Test your changes". — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- What belongs where: build commands, conventions, layout and "always do X" rules go in CLAUDE.md; "multi-step procedure or only matters for one part of the codebase" goes to a skill or path-scoped rule; personal preferences go in `CLAUDE.local.md` or `~/.claude/CLAUDE.md`. — [Claude Code memory docs](https://code.claude.com/docs/en/memory)
- Comparison table: CLAUDE.md loads every session, rules load every session or when files match, skills on demand; hooks have zero context cost unless they return output; skills cost descriptions every request. "Every feature you add consumes some of Claude's context. Too much can fill up your context window, but it can also add noise that makes Claude less effective; skills may not trigger correctly, or Claude may lose track of your conventions." — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Determinism: instructions (prompt, CLAUDE.md, skill) are non-deterministic ("there's no guarantee that it'll follow your instructions"); hooks, deny rules and managed settings are deterministic. "Don't overdo it: a hook is for a rule with zero exceptions, and `Prefer named exports` has plenty." Also: delete hooks that encode mere preferences. — [Best practices](https://code.claude.com/docs/en/best-practices)
- `Stop` hook can enforce a check (exit code 2 sends Claude back to work), with a cap of 8 consecutive blocks by default. — [Best practices](https://code.claude.com/docs/en/best-practices)
- Subagents do not inherit the main conversation's auto memory (a fork does); Explore and Plan agents start without CLAUDE.md; subagents can keep their own persistent memory. — [Claude Code memory docs](https://code.claude.com/docs/en/memory), [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- AGENTS.md: Claude Code reads AGENTS.md directly in place of CLAUDE.md when no CLAUDE.md exists in a folder (from about v2.1.277 per Willison's note; docs describe built-in `cc-plugin-agents-md`), and recommends `@AGENTS.md` import inside CLAUDE.md for dual-tool repos. Remove any SessionStart hook that prints AGENTS.md since it would duplicate. — [Claude Code memory docs](https://code.claude.com/docs/en/memory), [Simon Willison, 18 Sep 2026](https://simonwillison.net/2026/Sep/18/thariq-shihipar/)
- Plugins package skills, hooks, subagents and MCP servers for reuse across repos; plugin skills are namespaced (e.g. `/my-plugin:review`). Skills and subagents override by name by priority; hooks from all sources merge and all fire; CLAUDE.md files are additive. — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Anthropic's engineering blog treats "structured note-taking" (agent writes notes outside the context window and reloads them) and compaction as the two long-horizon memory techniques, with just-in-time retrieval over pre-loading. — [Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Organization-wide CLAUDE.md can be deployed centrally, but "enforce rules with managed settings such as `permissions.deny`". — [Claude Code memory docs](https://code.claude.com/docs/en/memory)

### Inferences
- A workspace kit plugin should ship skills and hooks, and install a minimal CLAUDE.md template; the plugin cannot enforce workspace rules via CLAUDE.md alone, so lint and hook checks are where the kit's "rules" gain teeth.
- Because auto memory is per-machine and not versioned (and subagents don't see it), anything the user wants portable across machines, as the workspace kit requires, belongs in versioned files in the workspace, not in auto memory. The user's existing MEMORY.md-style index is compatible but should be treated as a convenience layer.

### Gaps
- Official documentation says nothing on automated promotion from corrections to rules beyond "when to add"; Anthropic offers no first-party reflect/retro command (only auto memory and, in the API, Dreams).
- Exact Claude Code version that introduced auto memory and `/doctor prompt-audit` details beyond the docs fragments above not independently verified.

## 5. What evidence exists on whether instruction files and memory improve outcomes, and where they fail?

### Takeaway
Evidence is mixed and thin. The best controlled study (ETH Zurich, ICLR 2026 listing) found context files generally do not improve task success and cost over 20 percent more, with human-written files giving at most small gains and LLM-generated files slightly hurting. A separate efficiency study found lower runtime and output tokens with AGENTS.md. Vercel's eval found passive AGENTS.md context beat on-demand skills for out-of-training-data API knowledge. Practitioner reports blame bloat, vagueness and stale or conflicting instructions for ignored rules.

### Cited Findings
**Studies**
- Gloaguen, Mundler, Muller, Raychev, Vechev, "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?" (arXiv 2602.11988, v1 12 Feb 2026, v3 29 Sep 2026): context files "do not generally improve task success rates" and raise inference cost by over 20 percent; holds for LLM-generated and developer-written files, across models and agents; agents follow the instructions (more exploration, testing, reasoning); repository overviews were not helpful; recommendation: use context files mainly for non-standard coding practices and evaluate any change before deploying. — [arXiv abstract](https://arxiv.org/abs/2602.11988)
- Secondary summaries of the same paper give numbers the abstract page does not: LLM-generated files lower success by about 0.5-2 percent, developer-written files give about 4 percent gain, scope was Python repos and four agents (Claude Code with Sonnet 4.5, Codex with GPT-5.2 and GPT-5.1 mini, Qwen Code), and when documentation was removed from repos, LLM-generated files helped by about 2.7 percent. Not verified against the full paper. — [ICLR listing / summary via search](https://iclr.cc/virtual/2026/10021235), [arxiviq](https://arxiviq.substack.com/p/evaluating-agentsmd-are-repository)
- Lulla et al., "On the Impact of AGENTS.md Files on the Efficiency of AI Coding Agents" (arXiv 2601.20404, Jan 2026): 10 repos, 124 small merged PRs, Codex with gpt-5.2-codex, paired runs with and without AGENTS.md. Median runtime fell from 98.57 s to 70.34 s (about 28.6 percent), mean output tokens fell about 20 percent; input tokens flat in medians. They did not measure correctness (only a manual sanity check of 50 outputs). — [arXiv 2601.20404](https://arxiv.org/html/2601.20404)
- Vercel evals on Next.js 16 APIs absent from training data: baseline 53 percent pass, skill with default behavior 53 percent (skill never invoked in 56 percent of cases), skill with explicit instructions 79 percent, compressed 8KB docs index in AGENTS.md 100 percent. Authors' caveats: self-built evals, gap may narrow with better tool use, wording-sensitive ("invoke first" missed project context), skills may suit vertical user-triggered workflows. — [Vercel blog](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)
- Descriptive studies: Agent READMEs (arXiv 2511.12884) analyzed 2,303 context files from 1,925 repos (structure and content, not effectiveness); "Configuring Agentic AI Coding Tools" (arXiv 2602.14690) found context files dominate configuration across 2,926 GitHub repos. Both from search-snippet summaries. — [arXiv 2511.12884](https://arxiv.org/pdf/2511.12884), [arXiv 2602.14690](https://arxiv.org/html/2602.14690)

**Practitioner failure reports**
- Common 2026 blog diagnosis of ignored CLAUDE.md: length, vagueness, buried rules, missing "why", conflicting or duplicate instructions; HumanLayer guide (via secondary excerpt) says Claude may skip instructions its system prompt deems irrelevant when not universally applicable; hooks recommended over prose for process rules. All secondary blogs; a Reddit allegation that Opus 4.6 ignored instructions or stopped loading referenced files is anecdotal. — [DEV Community](https://dev.to/promptmaster/why-claude-code-ignores-your-claudemd-and-how-to-fix-it-2bb0), [engineered.at](https://engineered.at/articles/if-claude-code-sometimes-skip-claude-md-file), [fooqux excerpt](https://fooqux.com/article/909)
- Wisetax: CLAUDE.md reached 700+ lines, volatile detail diluted every session, and auto memory was not shared across collaborators, motivating a versioned knowledge layer. — [DEV Community, szkjn](https://dev.to/szkjn/we-outgrew-claudemd-building-a-knowledge-layer-that-compounds-33f)
- Cursor removed its Memories UI and Generate Rules command within about a year of launching them; users reported lost or hard-to-manage memories. Evidence of a staleness and management problem for automatic memory, not of improved outcomes. — [Cursor forum](https://forum.cursor.com/t/are-my-memories-gone/144057)
- Anthropic's own docs concede the failure modes: contradictions resolved arbitrarily, adherence falling as files lengthen, instructions written for older models becoming dead weight (the reason `/doctor prompt-audit` exists), and emphasis causing over-application. — [Claude Code memory docs](https://code.claude.com/docs/en/memory), [Best practices](https://code.claude.com/docs/en/best-practices)
- Known limitation of memory consolidation tools: Dreams docs say line-level edit instructions generally produce no change because the pipeline is a synthesis pass; SkillOpt-Sleep and Dreams both stage or output a separate store for human review rather than overwriting. — [Dreams docs](https://platform.claude.com/docs/en/managed-agents/dreams), [SkillOpt-Sleep](https://github.com/microsoft/SkillOpt/blob/main/docs/sleep/README.md)
- Verification outweighs instructions in Anthropic's framing: "give Claude a way to verify its work" is called the most important tip by InfoQ's report of Cherny's workflow (claimed 2-3x improvement, unmeasured). — [InfoQ](https://infoq.com/news/2026/01/claude-code-creator-workflow/)

### Inferences
- The ETH result and Anthropic's "only what Claude can't work out from the code" rule agree: overviews, architecture summaries and style guides the model already infers add cost without gain; value sits in non-standard, non-derivable facts (commands, local conventions, gotchas, domain terms). That fits a workspace of client-specific vocabulary and decisions, where models cannot rely on prior knowledge (the paper itself flags niche or proprietary domains as where results may differ).
- Efficiency gains (Lulla) and success-rate losses (Gloaguen) are not contradictory: files change agent behavior (more exploration and testing) which can cut runtime in some tasks and raise cost or reduce success in others. Neither tested a self-improving, corrections-derived file, which is a different artifact from an init-generated one.
- Because no study shows a self-updating rules loop beats a static minimal file, the kit should treat any promoted rule as a hypothesis: record its origin correction, check it against the next occurrence, and drop it if the error does not recur or the rule is never relevant. This is the manual analog of SkillOpt's held-out gate, and of Anthropic's "start minimal and add based on observed failures" advice.
- Skills' discovery problem (56 percent never invoked in Vercel's eval) argues for keeping a short, always-on index in CLAUDE.md that names the skills or documents to consult, and for strong trigger descriptions, rather than relying on skill auto-selection for critical context.
- Caveat for the kit's evidence base: nearly all outcome evidence is Python/JS repo coding tasks; knowledge-work workspaces (docs lint, decisions, glossary) have no published evaluations.

### Gaps
- No study found that evaluates self-updating or correction-derived instruction files, memory loops, or retro commands against a control.
- Full text of arXiv 2602.11988 was not read; quantitative details come from secondary summaries and conflict slightly in author-name transliteration across sites.
- No evaluation of non-coding agent workspaces (documentation, design, ops).
- Hacker News discussions were not located in search results; no HN primary thread cited.
- Chroma context-rot and IFScale findings are from search summaries; neither was tested on instruction files in coding agents.
